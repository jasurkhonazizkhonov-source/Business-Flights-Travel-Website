* **Active probes (local build, ~150 requests, scripts kept outside the repository on F:):** image-optimizer abuse (SSRF, traversal, parameter confusion), path and redirect confusion, sensitive-file paths, forged `Host`/`X-Forwarded-*`, every HTTP verb, malformed Server Action bodies, cross-origin Server Action calls with the real action ids, raw markup in request paths.
* **Measurement:** dependency audit (website and, read-only, CRM), install scripts, integrity hashes, structural accessibility of all 223 routes, structured-data types, cache headers, lab performance (earlier task).

### Verified with no defect found

* **Injection / browser:** no `innerHTML`, `eval`, `new Function`, `document.write`, `child_process`, `fs`; the only raw-HTML sinks are 11 JSON-LD call sites whose payload is static data with `<` escaped (`\u003c`); no user value reaches an `href`, redirect or file path; `/flights?to=` is resolved against the airport dataset (only a known record is shown); `dynamicParams = false` on every dynamic segment; no prototype pollution (payload test, later requests unaffected).
* **SSRF:** the only server-side outbound requests are the CRM client (operator-set URL, `redirect: "error"`, bounded timeout) and the image optimizer (allow-listed host, allowed widths and qualities; 11 abuse variants refused).
* **E-mail injection:** every interpolated value in the notification e-mail is HTML-escaped, the subject carries only IATA codes and counts, and the e-mail validator rejects `?`, `&`, `%`, `;`, `,`, `<`, `=` and quoted local parts, so a `mailto:` link cannot carry `?bcc=`.
* **Headers:** normal pages and the 404 page carry the full set; Cache-Control is correct per route type.
* **Privacy:** no analytics, tag manager or other third-party script anywhere in the source; the only browser storage is the cookie-notice key in `localStorage`, no cookie, no session storage; logs are value-free (the log statements were read individually); the hint route returns no IP, city or coordinates and is `private, no-store`.
* **Structure:** all 223 pages have exactly one `h1`, no skipped heading level, a language and title, unique ids, named links/buttons/inputs, and `rel="noopener noreferrer"` on every `_blank` link.
* **Structured data:** `TravelAgency`, `WebSite`, `BreadcrumbList`, `FAQPage`, `Article`, `ImageObject` only; no rating, review, price, offer or opening-hours property anywhere.
* **Supply chain:** 2 packages with install scripts (optional macOS `fsevents`, dev-only `unrs-resolver`), 0 deprecated, every lockfile entry has an integrity hash and resolves from the npm registry (lockfile v3).
* **Signing:** the website's canonical message, the length-prefixing, the 120 s / 30 s window, the single-use nonce and the constant-time comparison match the CRM verifier read in this task; key rotation exists on the CRM (`LEAD_INGEST_SECRET_PREVIOUS`).
* **Forms:** server-side re-validation of every field, honeypot and timing checks, a 64 KB body cap, an in-flight guard on all three forms, idempotency keys, no false success on a CRM failure (tests from earlier tasks, re-run).
