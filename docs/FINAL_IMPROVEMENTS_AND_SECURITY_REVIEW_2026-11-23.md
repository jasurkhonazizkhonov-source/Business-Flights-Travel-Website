## 3. Deployment notes for a later, separately approved deployment

1. **CRM before website** (date flexibility, see `DATE_FLEXIBILITY.md` section 5).
2. `compose.yaml` now passes an empty `EDGE_PROOF_SECRET` through; empty means the feature is off, so deploying this build changes no behaviour until you decide to set it. If you do: create the Cloudflare request-header rule **first**, then set the value, then verify a real submission stores the visitor's IP (`IP_AND_LOCATION_CAPTURE.md` section 6).
3. `deploy/preflight.sh` refuses a set-but-too-short `EDGE_PROOF_SECRET`.
4. The device-location feature needs nothing at deployment; the optional location-header transform in the runbook (E3) stays unnecessary.
